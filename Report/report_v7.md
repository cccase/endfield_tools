# Endfield Rotation & SP Simulator v7 実装レポート

本レポートでは、ユーザー要望に基づき追加された新キャラクター「スー（Sue）」および「リーノ（Lino）」の実装内容とその技術的な詳細をまとめます。

## 1. 新キャラクターのデータ追加
`data/characters.json` に「スー」と「リーノ」を追加しました。

* **スー（Sue）**:
  * 戦技1（SPコスト: 0）と戦技2（SPコスト: 15）の2種類のスキルを持ちます。
  * 連携技と必殺技（EPコスト: 100）も設定されています。
* **リーノ（Lino）**:
  * 戦技（SPコスト: 25）、連携技、必殺技（EPコスト: 100）が設定されています。
  * `baseRefundSP: 10` の基本返還SPが設定されています。

## 2. スーのスキル依存関係（Skill Sequence Dependency）の実装
「スーがスキル1を打つと、スキル2が発動できる」という要件を満たすため、`updateSimulation` に状態管理を導入しました。

* `suSkill1CastCount` 変数を導入し、タイムラインの順次評価中に「戦技1」が発動された回数をカウントします。
* 「戦技2」のブロックが評価された際、`suSkill1CastCount` が0以下の場合はエラー状態と判断し、キャラクターの警告リスト（`epState[step.charId].warnings`）に「戦技2は戦技1の後に発動可能」という警告メッセージを追加します。
* 正常に「戦技2」が発動された場合は、`suSkill1CastCount` をデクリメント（消費）します。これにより、戦技1を1回打てば戦技2を1回だけ打てる仕様を再現しています。

## 3. リーノのSP返還メカニクスの実装
「連携技でSP20返還、それとは別でSP10返還もある」という要件を満たすため、リーノ固有の動的SP返還ロジックを実装しました。

* **シミュレーション内での処理（`updateSimulation`）**:
  * タイムライン評価時に `linoComboCount` 変数を用いて、直近で発動されたリーノの連携技の回数をカウントします。
  * ユーザーが明示的に「返還SP」ブロックを配置した際に、`(直近の連携技回数 * 20) + リーノの基礎返還SP(10)` を計算し、プールにSPを還元します。その後、`linoComboCount` を0にリセットします。
* **UI上での動的デフォルト値反映（`renderTimeline`）**:
  * タンタンの返還ロジックと同様に、タイムライン描画時に「返還SP」ブロックより前に配置されたリーノの連携技の数を逆算し、入力フォームのデフォルト値（value属性）が自動的に `(直近の連携技回数 * 20) + 10` になるよう実装しました。
  * これにより、ユーザーは手動で計算することなく、正しい返還SP値をシミュレーションに組み込むことができます。

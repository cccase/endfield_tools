# Endfield Rotation & SP Simulator v6 実装レポート

本レポートでは、V6の要件に基づき実装された変更内容とその技術的な詳細をまとめます。

## 1. 2段階必殺技と必殺キャンセル機能の追加
キャラクターデータ（`characters.json`）を拡張し、オクギに`ult2`（必殺技2）、タンタンに`ult_cancel`（必殺キャンセル）のスキルデータを追加しました。
これに伴い、`app.js` のシミュレーションロジック（`updateSimulation`）に新たな状態管理を導入しました。

* **EPロック（epLock）機構の導入**:
  * キャラクター個別の状態として `epLock` フラグを追加しました。
  * オクギが `ult`（必殺技1）を発動すると、この `epLock` が `true` になり、戦技や連携技によるEP獲得処理がスキップされるようになります。
  * その後、`ult2`（必殺技2）のブロックがタイムライン上で処理されると `epLock` が `false` に戻り、EPの蓄積が再開されます。
* タンタンの `ult_cancel` はEPロックを引き起こさず、タイムライン上の行動マーカーとして機能するように実装されています。
* また、UI上でこれらの特殊ブロックを区別しやすくするため、`style.css` に専用のカラークラス（`.bg-ult2`, `.bg-ult-cancel`）を追加し、レンダリングロジックを更新しました。

## 2. スキル使用回数の統計トラッキング
ユーザーがローテーションの効率をより詳細に分析できるよう、以下のトラッキング機能を追加しました。

* **全体戦技使用回数（SP返還を考慮した小数点カウント）**:
  * グローバル変数 `totalSkillCasts` を導入しました。
  * スキル（戦技）使用時に返還SPプールからSPを消費するロジックの直後に、`(スキルの本来のコスト - 消費した返還SP) / スキルの本来のコスト` という計算式で「実質的なスキル使用回数割合」を算出し、これを加算しています。
  * 計算結果は小数第2位まで（例: `0.60`）フォーマットされ、画面上部のステータスサマリー領域に新設した項目に表示されます。
* **個別連携技使用回数**:
  * キャラクターの状態オブジェクト（`epState`）内に `comboCount` プロパティを追加しました。
  * 連携技（combo）のブロックが処理されるたびにインクリメントされ、各キャラのEPバーの上部（必殺発動回数の横）に表示されるようにUIを更新しました。

## 3. モバイル向けUIレイアウトの最適化
スマートフォンなどの狭い画面でのドラッグ＆ドロップ操作の快適性を劇的に向上させるため、モバイル専用のCSS（メディアクエリ `max-width: 768px`）を実装しました。

* **タイムラインの縦型カラム化**:
  * `#timeline-wrapper` を横方向のフレックスコンテナ（`overflow-x: auto`）に変更しました。
  * 各サイクル（`.cycle-wrapper`）を縦方向のフレックス（`flex-direction: column`）とし、画面幅の40%（`40vw`）の固定幅を持たせることで、iPhone等の画面内に約2列のカラムが余裕を持って並ぶように設計しました。
  * カラム内ではスキルブロックが縦に積み重なり、ドロップゾーンも下部に配置されるため、スマホの縦スクロール操作と相性が良くなっています。また、待機（セパレーター）ブロックは縦積みレイアウトに合わせて横線（`border-top`）として描画されるよう調整しました。
* **スキルパレットの下部固定（Sticky）**:
  * `.palette-panel` を `position: fixed; bottom: 0;` に設定し、画面下部に常時表示されるようにしました。
  * 背後のタイムラインと被って見づらくならないよう、パレット部分の背景をソリッドな暗色（`#1e1e1e`）に設定し、`body` にパディング（`padding-bottom: 200px`）を持たせてタイムラインの最下部が隠れないように調整しています。
